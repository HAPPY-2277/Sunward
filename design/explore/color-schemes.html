与产品理念的贴合

  • 与启动图标、首页 logo 同一套朝阳金——品牌第一次「图标 / 界面」完全一致。

与产品理念的贴合

  • 「运动 App 最经典的一口橙」：FitoTrack（GPL，多年维护）用同色做主色，久经验证不刺眼、不分性别年龄。
  • 次色用骑行棕而非红：全家感的暖棕替代警示感红系，符合「不做裁判」。
  • FitoTrack 原版在橙上压白字只有 2.4:1，长辈看不清——本方案改成深墨字（7.6:1），这是「成熟方案 + 家人标准」的修正点。

附录 B · 「改浅色底」对项目的影响评估

回答本次的先行问题：改动大不大、会不会毁坏项目。结论：工程量中等、完全可控；数据层零接触，「毁坏项目」的可能性约为零（git 分支可回滚，所有改动集中在视觉层）。

要动什么（按影响从大到小）

  1. colors.xml 全量重映射（1 个文件，115 行 / 约 110 个令牌）：现有结构是集中式设计令牌，全部通过名字引用——这是本项目最好的消息，浅色化主要就是重写这一份文件。其中 white_04…95 的白色透明度阶梯（深底专用）需整体反转为暖墨透明度；lime_XX / orange_XX alpha 梯度换新主色即可。
  2. Kotlin 里 53 处硬编码色值（7 个文件）：自绘 Canvas 控件没有走资源令牌，逐处改：TrendChartView.kt（柱 / 线 / 点 / 气泡，14 处）、TrackCanvasView.kt（轨迹 / 起终点，6 处）、TrackThumbView.kt（纸底 / 轨迹，7 处）、CityMapView.kt（手绘地图 9 常量 + 7 个注记色——它本来就是浅色纸底 #E9EEE4，浅主题反而更统一）、PaceCurveView.kt（4 处）、WeekBarsView.kt（1 处）、ReportBuilder.kt:294-317（运动构成三色，建议顺势换成各案的「同族三阶」）。建议借机把这些 Color.parseColor("#…") 改为引用 colors.xml 令牌，一次还清技术债。
  3. themes.xml（15 行）：parent 从 Theme.Material3.Dark.NoActionBar 换 Light，android:windowLightStatusBar 改 true（浅底配深色图标），状态栏 / 导航栏色换浅色。仍是「全局唯一主题、不随系统切换」，架构不变。
  4. drawable 层：bg_pill_lime 等内嵌荧光绿的背景 drawable 换新主色版本；scrim / 遮罩色换暖黑。
  5. 文档同步：产品理念 §六「视觉基调」（深色 + 荧光绿 → 暖色浅底）、README「名称与图标」的品牌色表述、design/prototype 视觉基线说明。

完全不碰什么（= 毁坏风险为零的部分）

  • 数据层：SQLite、RunRepository、ReportBuilder 的统计口径——一行不动，家人的跑步记录不受任何影响。
  • 算法红线：坐标系（WGS-84 / GCJ-02）、EMA 距离平滑、状态机、前台服务类型——全部与颜色无关。
  • 品牌资产：启动图标、首页 logo（朝阳金）保持不变，浅底方案与它是同一色族。

真实的风险在哪里（都有对策）

  • 对比度回归：深底方案里「白字怎么都够对比」，浅底不行——本文件每案都给出实测对比度表，落地时按表验收，全站正文 ≥4.5:1。
  • 漏改的硬编码色：grep 只有 53 处但分散在 7 个文件，靠「逐页模拟器走查」兜底：GO→暂停→继续→结束→成绩页、记录页筛选与展开、报告周 / 月 / 年切换、强杀恢复提示。
  • 深浅判断惯性：白色透明度阶梯在浅底会「消失」，需按新令牌整体替换，不能只改主色。
  • 回滚成本：单独分支（如 feat/light-theme-warm）一次提交完成主体，出问题 revert 即回到现状，不污染 main。

建议的落地顺序（方案确认后执行，本次不实施）

  1. 分支 feat/light-theme-warm，重写 colors.xml（按选定方案的映射表）。
  2. themes.xml 换 Light parent + 状态栏设置；新增 / 替换相关 drawable。
  3. 7 个 Kotlin 文件的硬编码色改为资源引用（顺手还债，不改逻辑）。
  4. gradlew testLocalDebugUnitTest（纯逻辑 59 个测试应全绿）+ assembleLocalDebug / assembleAmapDebug。
  5. 模拟器 local 变体逐页走查 + 截图入 docs/screenshots/；amap 变体真机确认。
  6. 同步产品理念 §六、README，验收报告补记录。
