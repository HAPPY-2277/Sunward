### 关键技术点

| 点 | 做法 |
|---|---|
| 定位源 | 系统 `LocationManager` + `GPS_PROVIDER`（`NETWORK` 兜底），**不依赖 Google Play 服务** |
| 采样 | `minTime=1000ms`、`minDistance=0`，1Hz |
| 去漂移 | 四步过滤链（精度 >30m / 时间戳非递增 / 速度 >12m·s⁻¹ / 与传感器速度严重不符） |
| **距离累加** | 对**每步位移向量**做 EMA（α=0.3）再累加，`≥0.6m` 才计入。直接累加会把静止抖动算进去；直接平滑经纬度会衰减稳定速度、距离少算 60% 以上 |
| 当前配速 | 速度 EMA（α=0.4）取倒数，限幅 2'30"–15'00"/km，无信号显示 `--'--"` |
| 调试面板 | **仅 debug 构建可见**（`ApplicationInfo.FLAG_DEBUGGABLE`），release 包点 GPS 胶囊无反应 |

### 架构要点

| 点 | 做法 |
|---|---|
| 状态归属 | 状态活在 `RunSession`（进程内单例）+ `RunForegroundService`；Activity 只观察 `StateFlow` 并下发 Intent 指令，自身无状态 → 旋转/锁屏/重建都不丢 |
| 状态机 | `IDLE → RUNNING ⇄ PAUSED → FINISHED`，非法迁移一律返回 false 并保持原状态；`FINISHED` 为终态 |
| 计时 | 全部基于调用方传入的单调时钟（生产用 `SystemClock.elapsedRealtime()`），**不用 `currentTimeMillis`**，用户改时间/跨时区不会错乱；暂停时把区间累加进 `accumulatedMs` |
| 前台类型 | `location`，刻意**不用 `dataSync`**（Android 15 起 dataSync 每 24h 最多 6 小时被系统停） |
| 5 秒限制 | `startForeground` 在 `onCreate` 内完成，不依赖 `onStartCommand` |
| 通知 | 独立渠道 `run_tracking`（IMPORTANCE_LOW、无声、不弹横幅）、`setOngoing(true)`、`setOnlyAlertOnce(true)`、`setSilent(true)`；两个 action 走 `PendingIntent.getService`（`FLAG_IMMUTABLE`） |
| 崩溃恢复 | 服务每秒 tick、**每 5 秒**把进行中快照写入 `InProgressStore`；重开时 `HomeActivity` 检查快照并弹窗 |

### 计划外偏差（3 项）

| # | 偏差 | 原因 | 影响 |
|---|---|---|---|
| D11 | 进行中快照用 **SharedPreferences（JSON）**，不是计划写的 SQLite | SQLite 表结构与 DAO 属 M6 范围，M3 只需「重启能提示恢复」这一行为 | 行为一致；M6 落 SQLite 时替换实现即可，调用方不变 |
| D12 | **卡路里提前到 M3** 实现（原计划 M4） | 三栏指标里「消耗」若长期显示 0 与原型不符；公式只有一行 `距离(km)×体重(kg)×1.036` | 体重固定 60 kg（附录 C 问题 2 的默认值）；M4 只补步频等 |
| D13 | 调试面板的模拟开关语义改为「**重新开始一次记录**」 | 切换数据源后原来的轨迹与距离没有意义；且界面文案改为**只由 `RunSession.state.simulated` 驱动** | 期间修掉一个真 bug：`RunUiState.simulated` 原先取 `lastPoint.simulated`，切到模拟后仍被上一个 GPS 点「骗回」false，导致开关失效 |
