# 修复轮 · GO 脉冲环提亮 + 周节奏卡铺满密排（分支 `feat/light-theme-warm`）

**执行日期**：2026-10-28　**状态**：✅ 单元测试与双变体构建通过、模拟器（local 变体）实测截图已留档；⏳ 待用户验收

> 用户指出首页两处视觉问题：(1) GO 组件外脉冲环太淡，看不清；(2) 本周节奏卡片周一至周日没有均匀铺满，每天条柱排列不紧密。
> 交付物为 HTML 修改方案 [design/explore/go-ping-and-week-bars-plan.html](../../design/explore/go-ping-and-week-bars-plan.html)（探索稿，落地后 `design/prototype/` 已同步为基线，见 §4）。

### 1. 问题定位

| 问题 | 现状（代码事实） | 后果 |
|---|---|---|
| GO 脉冲环太淡 | `res/drawable/bg_go_ping.xml`：`<stroke android:width="1dp" android:color="@color/ink_18"/>`（`ink_18` = 18% 墨 `#2E2C2C2A`） | 环落在饱和琥珀 hero 卡（`accent_lime #EF9F27`）上，1dp + 18% 墨几乎分辨不出轮廓 |
| 周节奏卡不铺满 | `ui/widget/WeekBarsView.kt`：柱宽常量 `barWidth = 20f * density`、间隙 `barGap = 4f * density`，7 根共 `7×20 + 6×4 = 164dp` | 393dp 屏上卡片内容区 313dp，柱子只占 52%，左右各空 74.5dp；柱子是「排在一起的一小撮」而不是「一周」 |

### 2. 改动内容

**2.1 GO 脉冲环（`android/app/src/main/res/drawable/bg_go_ping.xml`）**

- 描边 `1dp` → `1.5dp`；颜色 `@color/ink_18` → `@color/ink_40`（40% 墨 `#662C2C2A`）。
- `ink_40` 令牌已存在于 `colors.xml`，**未新增任何令牌**。
- 形制仍是「一圈细描边向外扩散并淡出」，**不动动画本身**：`HomeActivity.startGoPing()` 的 2.4s / `PathInterpolator(0f,0f,.2f,1f)` / scale 1→2 / alpha 1→0 全部保留。
- 选墨色而非奶油色的理由：奶油描边会消失在亮琥珀底里；墨色 40% 既提亮轮廓，又与 `design/explore/component-styles.html` 的 `rgba(44,44,42,.18)` 墨色系同源；同时保留「细描边」形制，不重演历史上「实心圆盘 + 描边」放大后变成一圈甩不掉黑边的老问题（该坑已写进该 drawable 的注释）。

**2.2 周节奏卡（`android/app/src/main/java/com/runclub/android/ui/widget/WeekBarsView.kt`）**

- 删除常量 `barWidth = 20f * density`；新增 `minBarWidth = 16f * density`（窄屏兜底）与 `barWidthFor(columnWidth)`。
- 排布算法改为**等分 7 列铺满视图宽度**：

  ```kotlin
  val columnWidth = width / 7f
  val barWidth = barWidthFor(columnWidth)          // = (columnWidth - barGap).coerceAtLeast(minBarWidth)
  fun centerX(i: Int) = columnWidth * i + columnWidth / 2f
  ```

  柱子在列内居中，**柱间间隙恒定 4dp**（`barGap` 含义由「固定间隙」变为「间隙不随屏宽变化」）。
- 今日整列衬底半宽由 `step / 2f` 改为 `columnWidth / 2f - 1f * density`，衬底按整列宽铺。
- **未动**：柱高口径（当日运动时长分钟，按本周最大值归一化）、`barMaxHeight 92dp`、`barMinHeight 6dp`、七色 `week_day_1..7` 映射、今日「X 分」chip、未来日留空不画假柱、控件高度 168dp、控件本身 `match_parent`。

| 屏宽 | 视图宽（屏宽−80dp） | 列宽 ÷7 | 柱宽（列宽−4dp） |
|---|---|---|---|
| 393dp | 313dp | 44.7dp | ≈ 40.7dp |
| 360dp | 280dp | 40.0dp | ≈ 36.0dp |
| 412dp | 332dp | 47.4dp | ≈ 43.4dp |

### 5. 界面实测（模拟器 local 变体）

**模拟器可用性**：报告 13 §6 记录的「宿主机虚拟化故障」本轮**不再复现**。当前可用启动方式（记录备查）：

```

ANDROID_USER_HOME = D:\Sunward\tools\android-user
ANDROID_AVD_HOME  = D:\Sunward\tools\android-user\avd
ANDROID_EMULATOR_HOME = D:\Sunward\tools\android-user

  -gpu swiftshader_indirect -port 5554 -no-metrics -no-window \
```

### 6. 已知取舍

- 柱宽随屏宽变化（36–44dp），属自适应预期；比例关系、色彩、今日强调均不变。
- 柱区上方仍留白：柱区可用高 124dp 而 `barMaxHeight` 仍为 92dp，上方约 32dp 空白本轮不动 —— 抬高会改变「柱高 = 当日运动时长」的视觉比例，超出本次诉求。

- 高德底图下脉冲环的实际观感未在真机验证。
