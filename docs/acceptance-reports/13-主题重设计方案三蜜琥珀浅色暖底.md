### 8. 改动内容

**8.1 GO 脉冲环（`android/app/src/main/res/drawable/bg_go_ping.xml`）**

- 描边 `1dp` → `1.5dp`；颜色 `@color/ink_18` → `@color/ink_40`（40% 墨 `#662C2C2A`）。
- `ink_40` 令牌已存在于 `colors.xml`，**未新增任何令牌**。
- 形制仍是「一圈细描边向外扩散并淡出」，**不动动画本身**：`HomeActivity.startGoPing()` 的 2.4s / `PathInterpolator(0f,0f,.2f,1f)` / scale 1→2 / alpha 1→0 全部保留。
- 选墨色而非奶油色的理由：奶油描边会消失在亮琥珀底里；墨色 40% 既提亮轮廓，又与 `design/explore/component-styles.html` 的 `rgba(44,44,42,.18)` 墨色系同源；同时保留「细描边」形制，不重演历史上「实心圆盘 + 描边」放大后变成一圈甩不掉黑边的老问题（该坑已写进该 drawable 的注释）。

**8.2 周节奏卡（`android/app/src/main/java/com/runclub/android/ui/widget/WeekBarsView.kt`）**

- 删除常量 `barWidth = 20f * density`；新增 `minBarWidth = 16f * density`（窄屏兜底）与 `barWidthFor(columnWidth)`。
- 排布算法改为**等分 7 列铺满视图宽度**：

  ```kotlin
  val columnWidth = width / 7f
  val barWidth = barWidthFor(columnWidth)          // = (columnWidth - barGap).coerceAtLeast(minBarWidth)
  fun centerX(i: Int) = columnWidth * i + columnWidth / 2f
  ```

  柱子在列内居中，**柱间间隙恒定 4dp**（`barGap` 含义由「固定间隙」变为「间隙不随屏宽变化」）。
- 今日整列衬底半宽由 `step / 2f` 改为 `columnWidth / 2f - 1f * density`，衬底按整列宽铺。
- **未动**：柱高口径（当日运动时长分钟，按本周最大值归一化）、`barMaxHeight 92dp`、`barMinHeight 6dp`、七色 `week_day_1..7` 映射、今日「X 分」chip、未来日留空不画假柱、控件高度 168dp、控件本身 `match_parent`。

## 第四轮 · 脉冲环定稿：墨 85% + 1.5dp

> 用户在 6 组候选中选 **C（实心墨 100% + 2dp）**，并指定改为**不透明度 85%、描边保持 1.5dp** —— 取 C 的「深墨」方向，不取它的粗描边。本轮已落地代码。

### 16. 改动内容

| 文件 | 改动 |
|---|---|
| `android/app/src/main/res/values/colors.xml` | 新增一行 `<color name="ink_85">#D92C2C2A</color>`（紧邻 `ink_60`，沿用「墨色 alpha 阶梯」命名法；85% × 255 ≈ 217 = `0xD9`） |
| `android/app/src/main/res/drawable/bg_go_ping.xml` | `<stroke android:width="1.5dp" android:color="@color/ink_85" />`（宽度不变，颜色 `ink_40` → `ink_85`）；注释补记两轮提亮的来龙去脉 |
| `design/prototype/activity.html` | 第 58 行 GO 环 `border-[#2C2C2A]/40` → `border-[#2C2C2A]/[0.85] border-[1.5px]`（原型用 Tailwind 任意不透明度写法 `/[0.85]`，默认刻度里没有 85） |
| `design/explore/go-ping-and-week-bars-plan.html` | 方案稿预览按 **Android ARGB 语义**修正颜色渲染：`colors.xml` 用 `#AARRGGBB`（alpha 在最前），CSS 8 位十六进制是 `#RRGGBBAA`（alpha 在最后），直接照抄会把「墨 85%」画成「#D92C2C @ 16.5%」，导致预览里的脉冲环比真实效果淡得多。已全部改为 `rgba(44,44,42,.85)` 一类写法；同时把静帧环从 `transform: scale()` 改为按比例设置 `width/height/border-width`，避免浏览器缩放栅格化把描边削成发丝线 |

**对比度（按 WCAG 公式对琥珀底 `#EF9F27` 离线计算，非仪器实测）**：

| 档位 | 令牌 | 实际值 | 描边 | 峰值（scale 1.00） | 中段（scale 1.45，动画 α 0.55） |
|---|---|---|---|---|---|
| 改前 | `ink_18` | `#2E2C2C2A` | 1dp | 1.12:1 | 1.06:1 |
| 第 1 轮 | `ink_40` | `#662C2C2A` | 1.5dp | 1.97:1 | 1.43:1 |
| **第 4 轮定稿** | **`ink_85`** | **`#D92C2C2A`** | **1.5dp** | **4.87:1** | **2.24:1** |

> 取 85% 而非 100% 的理由：两者肉眼几乎同深（差 15% 墨），但 100% 实墨会与 GO 墨盘糊成一体、失去「一圈淡墨描边向外扩散」的心智；85% 保留描边质感，同时峰值越过 3:1 非文本参考线。描边保持 1.5dp：粗描边在 scale 2.0 时会变成一条实边，与历史上「甩不掉的黑边」问题同源。
